## 한눈에 보기

| 메서드 | 방향 | 반환 | 시간복잡도 | 핵심 포인트 |
|--------|------|------|-----------|------------|
| `Integer.toString(i, radix)` | int → n진법 str | `String` | O(log i) | **제일 범용**, radix 2~36 |
| `Integer.parseInt(str, radix)` | n진법 str → int | `int` | O(len) | 코테 기본값 |
| `Integer.valueOf(str, radix)` | n진법 str → Integer | `Integer` | O(len) | 객체 반환 |
| `Long.parseLong(str, radix)` | n진법 str → long | `long` | O(len) | 큰 수 대비 |
| `Integer.bitCount(i)` | int → 1인 비트 수 | `int` | O(1) | popcount |
| `Integer.numberOfLeadingZeros(i)` | 앞(MSB)쪽 0 개수 | `int` | O(1) | 0이면 32 반환 |
| `Integer.numberOfTrailingZeros(i)` | 뒤(LSB)쪽 0 개수 | `int` | O(1) | 2로 몇 번 나뉘나 |

> **한 줄 요약**: 진법 변환은 `parseInt(str, radix)` ↔ `toString(i, radix)` 한 쌍으로 90% 커버되고, radix는 항상 **2~36** 범위. 결과가 21억 넘으면 `Long`으로.

## 1. 진법 변환 — 범용 메서드

### `Integer.toString(int i, int radix)` — int를 n진법 문자열로

```java
Integer.toString(13, 2);   // "1101"
Integer.toString(13, 8);   // "15"
Integer.toString(13, 16);  // "d"
```

- **radix(진법)는 2~36만 유효** (0~9 + a~z = 36개 문자)
- 범위 벗어나면 → 10진법으로 처리됨

### `Integer.parseInt(String str, int radix)` — n진법 문자열을 int로

```java
Integer.parseInt("1101", 2);  // 13
Integer.parseInt("12", 3);    // 5  (3진법 "12" = 1*3 + 2)
Integer.parseInt("ff", 16);   // 255
```

### `valueOf` vs `parseInt` — 반환 타입 차이만 인지

```java
int    a = Integer.parseInt("1101", 2);  // int 기본형
Integer b = Integer.valueOf("1101", 2);  // Integer 객체
```

- 코테에선 `parseInt`가 보통 더 편함 (오토박싱 오버헤드 없음)

### `Long.parseLong(String str, int radix)` — 큰 수일 때

```java
long big = Long.parseLong("11111111111111111111", 2);
```

- 결과가 **int 범위(약 21억)** 넘으면 무조건 `Long` 사용

## 2. 진법 변환 — 단축 메서드

radix를 고정한 버전. `toString(i, 2)`로 다 커버되니 **외우기 우선순위는 낮음**.
다만 남의 풀이 읽을 때 자주 나오니 눈에는 익혀둘 것.

```java
Integer.toBinaryString(13);  // "1101"  (radix 2 고정)
Integer.toOctalString(13);   // "15"    (radix 8 고정)
Integer.toHexString(13);     // "d"     (radix 16 고정)
```

## 3. 비트 패밀리

```java
Integer.bitCount(13);             // 3   → 1인 비트 개수 (popcount)
Integer.highestOneBit(13);        // 8   → 최상위 1비트만 남김 (1000)
Integer.lowestOneBit(12);         // 4   → 최하위 1비트만 (0100)
Integer.numberOfLeadingZeros(1);  // 31  → 앞쪽 0 개수
Integer.numberOfTrailingZeros(8); // 3   → 뒤쪽 0 개수
Integer.reverse(13);              // 비트 순서 전체 뒤집기
```

## 4. numberOfLeadingZeros / TrailingZeros 이해

### 핵심 전제: `int`는 항상 32비트 고정 박스

숫자가 작아도 앞쪽은 0으로 꽉 채워져 있다.

### `numberOfLeadingZeros(1)` → 31

`1`을 32비트로 펼치면:

```
0000 0000 0000 0000 0000 0000 0000 0001
└─────────── 0이 31개 ───────────┘ └1┘
```

**왼쪽(MSB)부터** 1이 처음 나올 때까지 0을 센다. 1은 맨 끝에 있으니 앞에 0이 31개. → `31`

> leading = "앞에 오는", 즉 **위쪽 빈 칸 개수**

### `numberOfTrailingZeros(8)` → 3

`8` = `1000`:

```
... 0000 1000
         └┬┘
       뒤에 0이 3개
```

**오른쪽(LSB)부터** 1이 처음 나올 때까지 0을 센다. 1 뒤에 0이 3개. → `3`

> trailing = "뒤따라오는", 즉 **아래쪽 0 개수**

### 한눈에 비교

```
       8 = 0000...0000 1000
                       │  └─ trailing zeros = 3 (오른쪽 끝부터)
                       └──── 여기 위로 전부 leading zeros = 28
```

| 메서드 | 세는 방향 | `8`(=1000) 기준 |
|--------|----------|----------------|
| `numberOfLeadingZeros` | 왼쪽(MSB)부터 → 1 만나면 멈춤 | 28 |
| `numberOfTrailingZeros` | 오른쪽(LSB)부터 → 1 만나면 멈춤 | 3 |

검산: 8은 leading 28 + 1비트 1개 + trailing 3 = 32 ✅
(1비트가 여러 개면 그 사이 0은 어느 쪽에도 안 세짐)

### 직관 정리

- **trailing zeros** = 그 수가 2로 몇 번 나눠지나 (= 2의 몇 제곱이 인수인가). 8 = 2³이니 3.
- **leading zeros** = 32비트 안에서 그 수가 얼마나 "작은가". 작을수록 앞 0이 많음.

## 코테에서 바로 쓰는 패턴

```java
// 진법 ↔ 진법 변환 (3진법 → 10진법 → 2진법)
int decimal = Integer.parseInt("12", 3);    // "12"(3진법) → 5
String bin  = Integer.toString(decimal, 2); // 5 → "101"

// 오버플로 위험하면 Long
long big = Long.parseLong("11111111111111111111", 2);

// 1의 개수 세기
int ones = Integer.bitCount(13);            // 3

// 2의 거듭제곱 판별 (1비트만 있으면 2의 거듭제곱)
boolean isPow2 = (n > 0) && Integer.bitCount(n) == 1;
```

### 외우기 우선순위 (실전 기준)

1. `Integer.parseInt(str, radix)` / `Integer.toString(i, radix)` — 진법 문제 90% 커버
2. `Long.parseLong(str, radix)` — 결과 큰 진법 문제 (오버플로 방지)
3. `Integer.bitCount(i)` — 비트 세기 단골
4. 나머지(단축형, 비트 조작) — 읽기용

## ❌ 하지 말 것

- ❌ `parseInt`/`toString`의 radix에 2~36 밖 값 넣기 → 10진법으로 처리됨
- ❌ 결과가 21억 넘는데 `Integer.parseInt` 사용 → 오버플로. `Long.parseLong` 써야 함
- ❌ `valueOf`(객체) / `parseInt`(기본형) 반환 타입 헷갈리기
- ❌ leading/trailing zeros 방향 헷갈리기 → leading=왼쪽(MSB), trailing=오른쪽(LSB)
- ❌ `numberOfLeadingZeros(0)`이 0일 거라 착각 → **32** 반환 (1이 하나도 없음)
