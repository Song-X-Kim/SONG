## 한눈에 보기

| 메서드 | 소속 | 시간복잡도 | 핵심 포인트 |
|---|---|---|---|
| `Integer.bitCount(int)` | `java.lang.Integer` | O(1) | 2의 보수 표현에서 **1의 개수**만 반환, 선행 0 무시 |
| `Long.bitCount(long)` | `java.lang.Long` | O(1) | `long`용 동일 메서드 |
| `Integer.toBinaryString(int)` | `java.lang.Integer` | O(n) | 정수 → 2진 문자열 (선행 0 없음) |
| `String.chars()` | `java.lang.String` | O(n) | 문자 스트림 → `filter().count()`로 1·0 둘 다 카운트 |

> **한 줄 요약**: 1의 개수는 `Integer.bitCount()` 한 방. 0까지 세려면 문자열로 풀거나 `Integer.SIZE - bitCount`.

## 1. 이진수 1·0 개수 세기

### 1-1. 정수의 1 비트 세기 — `Integer.bitCount`

```java
int n = 13;                        // 1101
int ones = Integer.bitCount(n);    // 3
```

- **시그니처**: `static int bitCount(int i)`
- **규칙**: 2의 보수 이진 표현에서 1로 세팅된 비트 수를 반환. 선행 0은 세지 않음.
- `Long.bitCount(long)`도 동일하게 존재.

0의 개수(32비트 전체 기준)는 빼서 구함:

```java
int zeros = Integer.SIZE - Integer.bitCount(n);  // 32 - 3 = 29 (선행 0 포함)
```

`Integer.SIZE`는 32.

### 1-2. 문자열로 다룰 때 (코테에서 흔한 경우)

이진수가 `"1101"` 같은 **문자열**이면 단일 메서드는 없고 직접 셈:

```java
String bin = "1101";
long ones  = bin.chars().filter(c -> c == '1').count();  // 3
long zeros = bin.chars().filter(c -> c == '0').count();  // 1
```

### 1-3. 주의 — 선행 0 차이

`Integer.toBinaryString(13)` → `"1101"` (선행 0 없음).
따라서 **문자열 길이 기준 0 개수**와 **`SIZE - bitCount` 기준 0 개수**는 다름.

| 방법 | 입력 | 시간복잡도 | 0의 의미 |
|---|---|---|---|
| `Integer.bitCount(n)` | `int` | O(1) | 1만 셈 |
| `chars().filter().count()` | `String` | O(n) | 문자열 안의 1·0 |
| `Integer.SIZE - bitCount(n)` | `int` | O(1) | 선행 0 **포함** 32비트 기준 |

## 2. 다음 큰 숫자 정석 풀이

> **문제**: 자연수 `n`이 주어질 때, `n`의 2진수 1의 개수와 **같은** 개수의 1을 가지면서 `n`보다 **큰** 자연수 중 **가장 작은** 수를 반환.
> 예: `n = 78` (1001110, 1이 4개) → `83` (1010011, 1이 4개)

### 2-1. 왜 이 접근인가

| 접근 | 설명 | 시간복잡도 | 평가 |
|---|---|---|---|
| **선형 탐색 (정석)** | `n+1`부터 1씩 올리며 `bitCount`가 같은 첫 수 찾기 | O(답까지의 거리 × 1) | 코드 단순, 제한 범위(`n ≤ 1,000,000`)에서 충분히 빠름 ✅ |
| 비트 트릭 (Gosper's hack) | 비트 연산만으로 다음 조합 직접 계산 | O(1) | 빠르지만 가독성↓, 코테 난도 대비 과함 |

프로그래머스 제한(`1 ≤ n ≤ 1,000,000`)에서는 선형 탐색으로 통과하며, `Integer.bitCount`가 O(1)이라 부담이 없음.

### 2-2. 정석 코드

```java
class Solution {
    public int solution(int n) {
        int target = Integer.bitCount(n);   // n의 1 개수
        int next = n + 1;
        while (Integer.bitCount(next) != target) {
            next++;
        }
        return next;
    }
}
```

- **시간복잡도**: O(d), d = `n`과 정답 사이 거리. 각 검사가 O(1).
- **공간복잡도**: O(1).

### 2-3. 동작 추적 (`n = 78`)

| 단계 | 값 | 2진수 | 1 개수 | 판정 |
|---|---|---|---|---|
| target | 78 | 1001110 | 4 | 기준 |
| +1 | 79 | 1001111 | 5 | ✗ |
| ... | 80~82 | ... | ≠4 | ✗ |
| 정답 | **83** | 1010011 | **4** | ✓ |

## 3. ❌ 하지 말 것

- ❌ `Integer.bitCount`로 **0의 개수**를 직접 얻으려 하기 — 1만 셈. 0은 `SIZE - bitCount` 또는 문자열로.
- ❌ `toBinaryString` 길이로 0을 세면서 `bitCount` 기반 0 개수와 같다고 가정 — 선행 0 처리가 달라 불일치.
- ❌ 다음 큰 숫자에서 `n`부터 시작 — 반드시 `n + 1`부터. (`n` 자신은 "더 큰" 수가 아님)
- ❌ `chars()`가 `char`가 아닌 `int`(IntStream) 스트림임을 잊고 `c == '1'` 대신 잘못된 비교 — `c`는 int지만 `'1'`과 비교 가능.
