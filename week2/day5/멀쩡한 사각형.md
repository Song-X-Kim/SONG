# 멀쩡한 사각형 — 대각선 격자 & gcd 완전 정리

> `W × H` 직사각형에 대각선을 그었을 때, **잘리지 않고 멀쩡히 남는 1×1 칸의 개수**를 구하는 문제.
> 핵심 공식 한 줄: **성한 칸 = `W*H - (W + H - gcd(W, H))`**

## 1. 30초 요약

```
망가진 칸 = W + H − gcd(W, H)
성한 칸   = W*H − (W + H − gcd(W, H))
```

| 한 줄 직관 | 의미 |
|---|---|
| 출발 칸 1개 | 선을 안 넘어도 첫 칸엔 이미 들어가 있다 |
| 세로선 W−1개 넘음 | 가로 W칸 사이 내부 경계선 수 |
| 가로선 H−1개 넘음 | 세로 H칸 사이 내부 경계선 수 |
| gcd−1만큼 빼기 | 꼭짓점에서 두 칸 셀 뻔한 걸 한 칸으로 바로잡음 |

> 전부 **"덩어리가 N개면 그 사이 이음매는 N−1개"** 라는 막대기 자르기의 변주다.

## 2. 유치원생 유도 (왜 이 공식인가)

### 2-1. 막대기 자르기 = 모든 것의 뿌리

막대를 **2번** 자르면 **3조각**. 0번 자르면 통째로 1조각.

```
조각 수 = 자른 횟수 + 1
```

> 경계(자르기)보다 덩어리(조각)가 **항상 1 더 많다.** 이 문장 하나가 아래 전부의 뿌리.

### 2-2. 출발 칸 +1

대각선을 좌하단 칸에서 출발시킨다. 아직 격자선을 하나도 안 넘었지만 **이미 칸 1개 안에 있다.**

```
관통 칸 = 1(출발 칸) + (넘은 선 수)
```

> 점에서 시작해도 그 점은 "첫 칸 안"에 있다. 막대기 1조각과 같다.

### 2-3. 넘는 세로선 W−1, 가로선 H−1

가로 `W`칸이면 세로선은 끝선 포함 `W+1`개. 그중 **맨 왼쪽(출발선)·맨 오른쪽(도착선)** 은 넘는 게 아니다. 양 끝 2개를 빼면:

```
넘는 세로선 = (W+1) − 2 = W − 1
넘는 가로선 = (H+1) − 2 = H − 1   (세로 방향, 같은 논리)
```

> 막대기 자르기 그대로: 칸 W개를 가르는 내부 경계는 W−1개.

### 2-4. 첫 공식: W + H − 1 (서로소 한정)

```
관통 칸 = 1 + (W−1) + (H−1)
        = W + H − 1
```

| 예 | 계산 | 결과 |
|---|---|---|
| 2×3 | 1 + 1 + 2 | 4 |

> ⚠️ 단, 이건 **W·H가 서로소**(공약수 1)일 때만 맞다. 아니면 과다 계산이 생긴다 → 2-5.

### 2-5. 함정: 꼭짓점을 동시에 넘을 때

우리 세는 규칙은 "세로선 넘으면 +1, 가로선 넘으면 +1". 보통은 따로 넘으니 문제없다.

그런데 대각선이 **격자 꼭짓점**(세로선·가로선이 만나는 점)을 정확히 지나면:

```
세로선 넘음 → +1
가로선 넘음 → +1
규칙대로면 +2  ← 두 칸 셈

하지만 실제로는 칸이 1개만 늘어남 (꼭짓점 콕 찍고 반대편 칸으로 바로 건너뜀)
```

> **+2로 셌는데 진짜는 +1.** 한 칸을 더 셌으니 그 1을 도로 빼야 한다.
> (예: 2×2는 단순 계산 3이지만 실제 관통 칸은 2)

### 2-6. 왜 gcd인가 — 기울기 약분

대각선 기울기를 비율로 쓰면 `W : H`. 이걸 **가장 간단한 정수비로 약분**한다.

```
8 : 12  →(둘 다 ÷4)→  2 : 3
         그 4 = gcd(8,12)
```

> **약분 = gcd로 나누기.** 그래서 "기울기 비율"과 "gcd"는 같은 얘기다.

약분된 비율 `(2,3)`이 대각선이 **정수 꼭짓점을 밟는 최소 보폭**이다.
(`(1,1.5)`처럼 더 작게는 분수가 끼어 꼭짓점을 못 밟음)

그 보폭으로 `(0,0)`→`(8,12)`까지 가면:

```
가로 8 ÷ 2 = 4걸음
세로 12 ÷ 3 = 4걸음
→ 총 4걸음 = gcd
```

발자국(정수 꼭짓점):
```
(0,0) ─걸음1─ (2,3) ─걸음2─ (4,6) ─걸음3─ (6,9) ─걸음4─ (8,12)
출발            점1          점2          점3            도착
```

> **걸음 수 = gcd.** 약분으로 나온 gcd가 곧 끝까지 가는 걸음 수가 된다.

### 2-7. 왜 −1인가 — gcd−1

발자국은 출발 포함 `gcd+1`개. 그중 **출발·도착**은 격자 모서리(꼭짓점 아님)라 뺀다.

```
내부 꼭짓점 = (gcd + 1) − 2 = gcd − 1
```

> 또 막대기 자르기! 걸음(블록) gcd개 → 그 사이 이음매 gcd−1개.
> 기차로 치면 객차 gcd칸 → 연결고리 gcd−1개 (맨 앞/뒤엔 고리 없음).

꼭짓점마다 1씩 과다 계산했으니, 전부 합쳐 `gcd−1`을 뺀다.

### 2-8. 완성 공식

```
망가진 칸 = (W + H − 1) − (gcd − 1)
          = W + H − 1 − gcd + 1
          = W + H − gcd        ← −1과 +1이 상쇄!
```

> 그래서 외울 땐 "gcd 빼기"가 맞고, 이해할 땐 "gcd−1 빼기 + 원래 −1과 상쇄"다.

```
성한 칸 = 전체 − 망가진 칸 = W*H − (W + H − gcd)
```

## 3. 한눈 정리표

| 조각 | 값 | 왜 |
|---|---|---|
| 출발 칸 | +1 | 선 안 넘어도 첫 칸엔 있음 (막대기 1조각) |
| 넘는 세로선 | W−1 | 가로 W칸 사이 내부 경계 |
| 넘는 가로선 | H−1 | 세로 H칸 사이 내부 경계 |
| 꼭짓점 과다분 | −(gcd−1) | 동시 통과 시 1칸 덜 세야 함 |
| **망가진 칸** | **W+H−gcd** | 위 넷 정리 |
| **성한 칸** | **W*H−(W+H−gcd)** | 전체 − 망가진 칸 |

**왜 gcd가 꼭짓점 흐름을 정하나 (핵심 한 줄)**
기울기 `W:H` 약분 → 기약비율이 최소 보폭 → 그 보폭으로 **gcd걸음** → 사이 내부 점 **gcd−1개**.

## 4. 복붙용 코드

```java
class Solution {
    public long solution(int w, int h) {
        // (long) 캐스팅을 곱셈 "전에" — int*int 오버플로 방지
        return (long) w * h - (w + h - gcd(w, h));
    }

    // 유클리드 호제법 (반복문 버전)
    private static int gcd(int a, int b) {
        while (b != 0) {
            int t = b;
            b = a % b;
            a = t;
        }
        return a;
    }
}
```

| 메서드/표현 | 시간복잡도 | 비고 |
|---|---|---|
| `gcd(a, b)` 유클리드 | O(log(min(a,b))) | 매 단계 값이 빠르게 줄어듦 |
| 전체 풀이 | O(log(min(w,h))) | gcd 한 번 + 산술 |
| 공간 | O(1) | 반복문 gcd는 추가 메모리 없음 |

> 재귀 gcd `return b == 0 ? a : gcd(b, a % b);` 도 동일 결과. 깊이가 얕아(O(log)) 스택 걱정 없음.

## 5. ❌ 실수 모음

| 실수 | 왜 틀림 | 고침 |
|---|---|---|
| `return w * h - ...` | `int * int`가 먼저 계산돼 오버플로 (w,h ≤ 10⁸ → 최대 10¹⁶ ≫ int 21억). long 변수에 담아도 이미 깨진 값 | `(long) w * h - ...` |
| `(long)(w * h)` | 괄호로 묶으면 int 곱셈 먼저 끝나고 캐스팅 → 늦음 | `(long) w * h` (캐스트가 `*`보다 우선순위 높음) |
| gcd를 빼야 하는데 `gcd−1`을 빼려 함 | 최종식은 `W+H−gcd`. `gcd−1`은 유도 중간값이고 원래 −1과 상쇄됨 | 외울 땐 그냥 `−gcd` |
| 작은 테스트만 통과 | `w*h`가 21억 안쪽이면 우연히 맞음. 큰 케이스에서 터짐 | 곱셈 21억 넘을 가능성 보이면 무조건 사전 `(long)` |

**오버플로 깨짐 흐름**
```
w=100000, h=100000
int*int = 10,000,000,000  → int 범위(약 2,147,483,647) 초과
       → 비트 잘려 엉뚱한 값(음수 등) → long에 그대로 담김 → 오답
```
