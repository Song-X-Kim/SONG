## 한눈에 보기

| 개념 | 결론 | 핵심 포인트 |
|---|---|---|
| 배열 원소 수정 `arr[i]=x` | 원본 반영 ✅ | 같은 객체를 가리키므로 호출자에게 보임 |
| 참조 재할당 `arr=new...` | 원본 무관 ❌ | 복사된 참조만 새 객체로, 호출자 무관 |
| `static` vs 인스턴스 메서드 | 차이 없음 | 전달 방식은 동일 |
| 회전 시 값 밀기 | "현재칸=이전값" 방향 | 진행 방향과 반대로 흘러야 회전 |
| 임시변수 `t` 역할 | 다음 칸 쓸 값 운반 | 백업만 하고 안 쓰면 무의미 |

> **한 줄 요약**: 자바는 "참조의 값"을 복사해 넘긴다. 원소를 고치면 같은 객체라 원본이 바뀌지만, 변수에 새 배열을 대입하면 그 순간부터 호출자와 무관해진다. 회전은 "한 칸 앞의 값을 들고 와 현재 칸에 쓰는" 운반 패턴이라, 백업한 임시값을 다음 반복에 **실제로 써야** 완성된다.

## 1. 배열을 인자로 넘기면 원본이 바뀌나?

### 핵심 규칙

자바는 **항상 값으로 전달(pass-by-value)** 한다. 단, 배열·객체를 넘길 때 복사되는 "값"은 **객체 자체가 아니라 그 객체를 가리키는 참조**다.

- 배열은 객체이고, 참조 값은 그 객체를 가리키는 포인터다. (JLS §4.3.1)
- 그래서 **메서드 안에서 원소를 수정하면**(`arr[i] = x`) 호출자와 메서드가 같은 객체를 보고 있으므로 원본에 반영된다.
- 하지만 **파라미터 변수에 새 배열을 대입하면**(`arr = new int[]{...}`) 복사된 참조만 다른 객체로 바뀔 뿐, 호출자의 참조는 그대로다.

### 예시 코드

```java
void modify(int[] arr) {
    arr[0] = 99;            // ✅ 원본 반영 (같은 객체)
    arr = new int[]{1, 2};  // 여기부터 로컬 참조만 새 객체
    arr[0] = 7;             // ❌ 원본 무관
}

int[] a = {0, 0, 0};
modify(a);
// a == {99, 0, 0}   ← arr[0]=99만 반영됨
```

### 2차원 배열도 동일

```java
void fill(int[][] grid) {
    grid[0][0] = 99;   // ✅ 원본 반영
}
```

`int[][]`는 "`int[]`을 원소로 가진 배열"이라, `grid`도 결국 한 객체를 가리키는 참조다. 원소(안쪽 배열) 수정은 그대로 호출자에게 보인다.

### `static`이든 인스턴스든 무관

전달 방식은 메서드 종류와 무관하다. `private int rotate(int[][] origin, ...)`이 `static`이어도 `origin`으로 원소를 고치면 원본 배열이 바뀐다. 그래서 회전 문제에서 **복사본을 만들 필요 없이** `origin`을 직접 in-place로 돌려도 된다.

## 2. 현재값·임시값 저장 및 반영 패턴

### 회전이란 무엇을 하는 것인가

테두리를 시계방향으로 한 칸씩 돌린다 = **각 칸이 "한 칸 뒤(이전 칸)의 값"으로 채워진다.** 값의 흐름은 칸을 도는 진행 방향과 **반대**다.

이걸 코드로 옮길 때 핵심은: 한 칸을 덮어쓰기 **전에** 그 칸의 원래 값을 백업해둬야, 다음 칸에 쓸 재료가 사라지지 않는다는 것.

### 올바른 운반 패턴

```java
int c = origin[start[0]][start[1]];   // ① 시작칸 값을 한 번만 들고 출발
min = Math.min(min, c);

for (int i = 0; i < 4; i++) {
    for (int j = 0; j < command[i]; j++) {
        start[0] += DIR[i][0];                 // ② 다음 칸으로 이동
        start[1] += DIR[i][1];
        int t = origin[start[0]][start[1]];    // ③ 이 칸 원래 값 백업
        origin[start[0]][start[1]] = c;        // ④ 들고 온 값을 여기 씀
        c = t;                                 // ⑤ 백업을 다음에 쓸 값으로 이어받기
        min = Math.min(min, c);
    }
}
```

### 변수 두 개의 역할

| 변수 | 의미 | 비유 |
|---|---|---|
| `c` | 지금 칸에 **써넣을** 값 (이전 칸에서 들고 온 것) | 손에 든 물건 |
| `t` | 지금 칸에 **원래 있던** 값 (덮어쓰기 전 백업) | 자리에 놓여있던 물건 |

흐름: 손에 든 `c`를 자리에 내려놓기 전에, 그 자리 물건 `t`를 집어 든다 → 손에 든 걸 내려놓는다 → 집어든 `t`가 다음 자리에 내려놓을 새 `c`가 된다. 이 "맞교환"이 한 칸씩 이어지며 회전이 완성된다.

### 변 길이(command) 계산

```java
int garo = query[3] - query[1];   // 가로 변 이동 횟수 = 칸수 - 1
int sero = query[2] - query[0];   // 세로 변 이동 횟수
int[] command = {garo, sero, garo, sero};
```

- 변의 **칸 수**는 `좌표차 + 1`이지만, **이동 횟수**는 모서리 칸이 다음 변과 겹치므로 `칸수 - 1` = 좌표차 그대로.
- 1-based 좌표 보정(`-1`)은 **인덱스 변환**에서만(`start = {query[0]-1, query[1]-1}`). 칸 수/이동 횟수 계산엔 영향 없다 (두 좌표를 빼면 보정이 상쇄됨).

## 디버깅 학습 포인트

### 잘못된 풀이 → 왜 실패 → 정답

**증상**: `min`이 첫 변에서만 맞고 둘째 변부터 틀어짐. (인덱스 초과가 아니라 값이 망가지는 버그)

**잘못된 코드**:
```java
int c = origin[start[0]][start[1]];   // 현재 칸 읽기
min = Math.min(min, c);
start[0] += DIR[i][0];
start[1] += DIR[i][1];
t = origin[start[0]][start[1]];       // 백업은 했는데
origin[start[0]][start[1]] = c;       // 다음 칸을 c로 덮음
// → 다음 반복에서 c를 또 origin[현재]로 새로 읽음
```

**왜 실패했나**:
1. `t`에 백업만 하고 **다음 칸 쓸 때 안 썼다.** 백업이 버려짐.
2. 다음 반복에서 `c = origin[현재칸]`을 새로 읽는데, 그 칸은 방금 덮어쓴 칸이라 **원래 값이 아닌 덮인 값**을 읽는다 → 첫 칸 값 하나가 변을 타고 줄줄이 복사된다.
3. `min`만 망가지기 전에 읽어서 첫 변은 우연히 맞고, 둘째 변부터 이미 덮인 값을 읽어 틀어진다.

**정답**: `c`를 매번 새로 읽지 말고, 백업해둔 `t`를 이어받는다 — `c = t`. 그래야 `t`(백업)가 실제로 일을 하고 회전이 완성된다.

```java
int t = origin[start[0]][start[1]];   // 백업
origin[start[0]][start[1]] = c;       // 들고 온 값 쓰기
c = t;                                // 백업을 다음 c로  ← 이 줄이 핵심
```

### (참고) 이전에 헤맸던 곁가지 버그

- `command = {garo, sero, garo, sero}`에서 `garo = 좌표차 + 1`로 두면 변마다 1칸씩 더 가 **인덱스 초과**. → 이동 횟수는 좌표차 그대로여야 함.
- 반대로 `garo = 좌표차 - 1`로 두면 1칸씩 모자라 테두리를 다 못 돔.
- `min`을 `0`으로 초기화하면 값이 모두 1 이상이라 항상 0 반환. → `Integer.MAX_VALUE` 또는 시작칸 값으로.

## 코테에서 바로 쓰는 패턴

### 1) 배열을 in-place로 고치는 헬퍼 — 복사 불필요

원본을 바꿔도 되는 상황이면, 인자로 받은 배열을 그대로 수정하면 호출자에 반영된다. 방어적 복사(`Arrays.copyOf` 등)는 원본을 보존해야 할 때만.

### 2) 한 칸씩 밀기 = "들고 와서 맞교환"

```java
int carry = arr[startIdx];          // 처음 한 칸만 손에 듦
for (다음 칸들...) {
    int backup = arr[here];         // 자리 물건 백업
    arr[here] = carry;              // 손에 든 거 내려놓기
    carry = backup;                 // 백업이 다음 carry
}
```

회전·시프트·뱀 이동 등 "이전 칸 값을 현재 칸으로 옮기는" 모든 문제에 재사용 가능.

### 3) 방향 배열(DIR)로 4방향 순회

```java
private static final int[][] DIR = {{0,1},{1,0},{0,-1},{-1,0}}; // 우 하 좌 상
start[0] += DIR[i][0];
start[1] += DIR[i][1];
```

### 시간·공간 복잡도

| 항목 | 복잡도 | 설명 |
|---|---|---|
| 쿼리 1개 회전 | O(변의 길이) | 테두리 둘레 = `2(garo+sero)`에 비례 |
| 전체 | O(Q × 테두리 둘레) | Q = 쿼리 수. 최악 한 쿼리가 전체 테두리면 O(rows+columns) |
| 공간 | O(1) 추가 | `c`, `t` 등 상수 개 변수만. 격자는 in-place 수정 |

## 하지 말 것

- ❌ 배열을 인자로 받아 **`arr = new int[]{...}`로 재할당**하고 원본이 바뀔 거라 기대하기 — 그 순간부터 호출자와 무관.
- ❌ 배열에 `a + b` 같은 **연산자** 쓰기 — 자바엔 배열 연산자 오버로딩 없음. 인덱스별 덧셈은 직접 루프.
- ❌ 회전에서 **`t`에 백업만 하고 안 쓰기** — 다음 칸 쓸 값으로 `c = t` 이어받지 않으면 한 값이 변 전체를 도배.
- ❌ 덮어쓴 칸을 다음 반복에서 **`origin[현재]`로 다시 읽기** — 원래 값이 아닌 덮인 값을 읽게 됨.
- ❌ `command`(이동 횟수)에 칸 수(`좌표차 + 1`)를 그대로 넣기 — 모서리 겹침으로 인덱스 초과.
- ❌ `min`을 `0`으로 초기화 — 값이 1 이상이면 항상 0 반환.
