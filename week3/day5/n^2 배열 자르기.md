## 한눈에 보기

| 버그 | 증상 | 원인 | 수정 |
|---|---|---|---|
| `(int) left / n` | 큰 입력서 행/열 깨짐 | 캐스트가 `/`보다 먼저 묶임 → int 오버플로 | `(int)(left / n)` |
| `i < end[0]` | 끝 행 통째 누락 → 뒤가 0 | right 행은 포함인데 `<`로 배제 | `i <= end[0]` |
| `int idx = 0;` (루프 안) | 앞칸만 덮어씀 | 행마다 0으로 리셋 | 루프 **밖**에서 1번 |
| `j < e` + `e = end[1]` | 끝 열 1칸 누락 | `<`는 배제 경계인데 포함값을 줌 | `e = end[1] + 1` |

**한 줄 요약:** 값은 `max(i, j) + 1` 공식으로 바로 구하고(그리드 X), 인덱스 경계는 *연산자와 경계값을 한 세트로* 맞춘다.

## 1. 캐스트 우선순위

```java
(int) left / n        // = ((int) left) / n   ← 캐스트가 먼저!
(int)(left / n)       // = 나눗셈 먼저, 그 다음 캐스트   ✅
```

**규칙**
캐스트는 단항(unary) 연산이라 곱셈/나눗셈(`* / %`)보다 우선순위가 높다. 즉 `(int) left / n`은 `left`에만 캐스트가 붙은 `((int) left) / n`으로 해석된다.

**왜 위험한가**
`left`는 최대 `n² - 1 ≈ 10¹⁴`까지 가능. `int`(약 ±21억)로 **먼저** 잘리면 값이 완전히 망가진 뒤 나눗셈이 일어난다. 큰 채점 케이스에서만 터지는 잠복 버그라 더 위험.

**올바른 방법**
```java
int row = (int)(left / n);   // left/n 은 long 연산, 결과 ≤ n-1 → int 안전
int col = (int)(left % n);   // left%n 도 결과 ≤ n-1 → int 안전
```

> 오늘 `answer` 크기는 `(int)(right - left + 1)`로 제대로 묶었으면서 start/end만 안 묶었다. **같은 괄호 패턴을 일관되게** 적용하면 됐던 부분.

## 2. 반열린 구간 — 연산자와 경계값은 한 세트

`for (int j = s; j < e; j++)` 에서 `j < e`는 **e를 포함하지 않는다.** j는 `s ~ e-1`까지만 돈다. 즉 `e`는 "여기 직전까지"라는 **배제(exclusive) 경계**. 수학으로 `[s, e)`.

**핵심: 비교 연산자와 경계값은 짝이다.**

| 연산자 | 경계 의미 | 마지막 열이 L일 때 e |
|---|---|---|
| `j < e` | 배제(exclusive) | `e = L + 1` |
| `j <= e` | 포함(inclusive) | `e = L` |

이 문제에 대입:

| 행 종류 | 포함할 마지막 열 | `<` 버전 e | `<=` 버전 e |
|---|---|---|---|
| 전체 행 | `n - 1` | `n` | `n - 1` |
| 끝 행 | `end[1]` | `end[1] + 1` | `end[1]` |

> 한쪽만 바꾸면(예: 연산자만 `<=`로) 딱 한 칸씩 어긋나서 off-by-one이 난다. 오늘 `j <= e`인데 `e = n`을 두는 실수와, `j < e`인데 `e = end[1]`을 두는 실수가 둘 다 이 짝을 깬 케이스.
>
> 시작 쪽 `s = start[1]`은 `j = s`부터 바로 실행되므로 **시작은 항상 포함**. +1 불필요.

## 3. idx 스코프

`idx`는 정답 배열 전체에 걸쳐 **누적되는 단 하나의 카운터**다.

```java
// ❌ 바깥 루프 안 → 행마다 0으로 리셋 → answer[0..] 계속 덮어씀
for (int i = ...) {
    int idx = 0;
    ...
}

// ✅ 루프 밖에서 한 번만 선언
int idx = 0;
for (int i = ...) {
    ...
    answer[idx++] = ...;
}
```

"각 행을 처리할 때마다 새로 0부터 쓴다"는 직관이 함정. 행이 바뀌어도 정답 배열에는 **이어서** 채워야 한다.

## 디버깅 학습 포인트

### (1) 캐스트 우선순위
- **잘못한 코드:** `int[] start = {(int) left / n, (int) left % n};`
- **왜 실패:** `((int) left)`로 먼저 잘려 큰 left에서 오버플로.
- **올바른:** `{(int)(left / n), (int)(left % n)}`

### (2) 끝 행 누락
- **잘못한 코드:** `for (int i = start[0]; i < end[0]; i++)`
- **왜 실패:** right가 들어있는 행 `end[0]`을 `<`가 통째로 배제 → 정답 뒷부분이 초기값 0으로 남음.
- **올바른:** `i <= end[0]`

### (3) idx 리셋
- **잘못한 코드:** 바깥 루프 안에서 `int idx = 0;`
- **왜 실패:** 행이 바뀔 때마다 idx가 0으로 돌아가 `answer` 앞부분만 덮어씀.
- **올바른:** 루프 밖에서 한 번 선언.

### (4) 경계 연산자/경계값 불일치
- **잘못한 코드 A:** `j <= e` 인데 전체 행 `e = n` → `j = n`(없는 열)까지 가서 유령 값 발생.
- **잘못한 코드 B:** `j < e` 인데 끝 행 `e = end[1]` → 끝 열 한 칸 누락.
- **왜 실패:** 연산자와 경계값이 짝이 안 맞아 한 칸씩 어긋남.
- **올바른:** `<` ↔ `e = end[1] + 1` / `<=` ↔ `e = end[1]` (위 표 참고).

### 버그가 합쳐졌을 때 — 실제 출력 추적
`n=3, left=2, right=5` (기댓값 `[3, 2, 2, 3]`), `i < end[0]` + `idx` 루프 안 + `e` 미보정 상태:
```
start = {0, 2}, end = {1, 2}, answer = new int[4]

i < 1  →  i = 0 만 실행 (행 1 누락 → answer[2], answer[3] = 0)
  i = 0: idx 여기서 0으로 리셋
         e = n = 3, j < 3  →  j = 2 만
         answer[0] = 3
끝.  →  결과 [3, 0, 0, 0]   ❌
```
앞 `3`만 맞고, 뒤 `0, 0`은 끝 행 누락. (다른 케이스에선 e 미보정으로 유령 값까지 끼어든다.)

## 복붙용 패턴

### 정답 풀이 (`<` 버전)
```java
class Solution {
    public int[] solution(int n, long left, long right) {
        int[] start = {(int)(left / n),  (int)(left % n)};
        int[] end   = {(int)(right / n), (int)(right % n)};
        int[] answer = new int[(int)(right - left + 1)];

        int idx = 0;
        for (int i = start[0]; i <= end[0]; i++) {
            int s = (i == start[0]) ? start[1] : 0;
            int e = (i == end[0]) ? end[1] + 1 : n;
            for (int j = s; j < e; j++) {
                answer[idx++] = (j < i) ? i + 1 : j + 1;
            }
        }
        return answer;
    }
}
```

### 대안 (`<=` 버전 — 경계값만 다름)
```java
for (int i = start[0]; i <= end[0]; i++) {
    int s = (i == start[0]) ? start[1] : 0;
    int e = (i == end[0]) ? end[1] : n - 1;   // <= 라 포함 경계
    for (int j = s; j <= e; j++) {
        answer[idx++] = (j < i) ? i + 1 : j + 1;
    }
}
```

### 캐스트-나눗셈 안전 패턴
```java
// long 값을 나눠 작은 int 결과를 얻을 때
int q = (int)(bigLong / smallInt);   // 나눗셈 먼저, 캐스트 나중
int r = (int)(bigLong % smallInt);
```

### 경계 매칭 셀프체크
```
연산자 < 이면  →  e = (마지막으로 포함할 인덱스) + 1
연산자 <= 이면 →  e = (마지막으로 포함할 인덱스)
시작 s 는 항상 포함 (보정 없음)
```

## ❌ 오늘 하지 말았어야 할 것

- 캐스트를 피연산자 전체에 안 씌우기 → `(int) x / n` (✅ `(int)(x / n)`)
- 비교 연산자만 바꾸고 경계값은 그대로 두기 (`<`↔`<=` 한쪽만)
- 누적 카운터 `idx`를 반복문 안에서 선언하기
- 정답 배열을 `int[] answer = {};` (크기 0)로 두고 나중에 `answer[idx]` 접근하기
- inclusive(`left`, `right`) 인덱스인데 끝을 `<`로 처리해 마지막 행/열 누락하기
