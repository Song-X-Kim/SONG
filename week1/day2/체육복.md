## 한눈에 보기

| 메서드 | 어디 소속 | 시간복잡도 | 핵심 포인트 |
|---|---|---|---|
| `Arrays.binarySearch(a, k)` | `java.util.Arrays` | O(log n) | 정렬 필수, 없으면 음수 반환 |
| `Arrays.sort(a)` | `java.util.Arrays` | O(n log n) | 원본 변경 |
| `coll.contains(o)` | `java.util.Collection` | 구현체마다 다름 | `equals` 기반 비교 |
| `set.add(e)` | `java.util.HashSet` | O(1) | 추가됐으면 `true` 반환 |
| `set.remove(o)` | `java.util.HashSet` | O(1) | 제거됐으면 `true` 반환 |

> **한 줄 요약** — "있는지/없는지" 자주 묻는 자료엔 무조건 `HashSet`. `ArrayList.contains` 루프 안에 넣으면 O(n²).

## 1. Arrays.binarySearch

### 시그니처

```java
public static int binarySearch(int[] a, int key)
```

### 반환값 규칙

| 상황 | 반환값 |
|---|---|
| 값을 찾음 | 해당 인덱스 (**0 포함**) |
| 값이 없음 | `-(insertion point) - 1` (음수) |

### ⚠️ 반드시 정렬되어 있어야 함

```java
int[] arr = {3, 1, 5};
Arrays.sort(arr);                       // ✅ 먼저 정렬
int idx = Arrays.binarySearch(arr, 5);
```

> 정렬 안 하면 컴파일 에러는 안 나지만 **결과가 undefined** (Oracle 공식 표현).

### ⚠️ 존재 체크는 `>= 0`

```java
// ❌ 0번 인덱스에서 찾은 경우 누락
if (Arrays.binarySearch(arr, p) > 0) { ... }

// ✅
if (Arrays.binarySearch(arr, p) >= 0) { ... }

// ❌ 없을 때 -1만 나오는 게 아니라 다양한 음수가 나옴
if (Arrays.binarySearch(arr, p) != -1) { ... }
```

### 시간복잡도

- 검색: **O(log n)**
- 정렬 포함: O(n log n) — 정렬 한 번 + 검색 여러 번일 때만 이득

> 💡 **언제 binarySearch 대신 HashSet?** 검색만 자주 할 거면 HashSet의 O(1)이 더 빠름. binarySearch는 정렬된 순서가 의미 있을 때 (e.g. 삽입 위치 계산).

## 2. Arrays는 어디에?

### `java.util.Arrays`

```java
import java.util.Arrays;     // 콕 집어
// 또는
import java.util.*;          // util 전체
```

### ⚠️ `java.util.*`는 하위 패키지 자동 포함 X

```java
import java.util.*;
import java.util.stream.*;   // Stream, Collectors는 따로 필요
```

`*`는 정확히 그 패키지의 클래스만 가져옴. 패키지 트리를 재귀적으로 안 탐.

### 코테 시작 시 import 템플릿

```java
import java.util.*;
import java.util.stream.*;
```

## 3. Collection.contains

### 정의 위치

```java
package java.util;

public interface Collection<E> {
    boolean contains(Object o);   // ← 여기서 정의
}
```

상속 구조:

```
Collection<E>
    ├─ List<E>     → ArrayList, LinkedList
    └─ Set<E>      → HashSet, TreeSet, LinkedHashSet
```

### 구현체별 성능 (★ 가장 중요)

| 구현체 | 시간복잡도 | 내부 동작 |
|---|---|---|
| `HashSet` | **O(1)** | 해시 버킷 직접 접근 |
| `TreeSet` | **O(log n)** | 이진탐색트리 (Red-Black Tree) |
| `LinkedHashSet` | **O(1)** | HashSet + 삽입 순서 보존 |
| `ArrayList` | **O(n)** | 처음부터 순회 |
| `LinkedList` | **O(n)** | 노드 순회 |

> **"있는지" 자주 체크하는 코드라면 무조건 HashSet 자료구조 선택.** 단 한 줄짜리 선택이 O(n²)을 O(n)으로 바꿈.

### 헷갈리는 것

#### Map은 `contains()` 없음

```java
Map<String, Integer> map = new HashMap<>();
map.contains("key");        // ❌ 컴파일 에러
map.containsKey("key");     // ✅
map.containsValue(123);     // ✅
```

#### String.contains는 완전 별개

```java
"hello".contains("ell");    // true — 부분 문자열 체크
```

- `String.contains(CharSequence)` — `java.lang.String` 메서드
- `Collection.contains(Object)` — 컬렉션 멤버 체크
- 이름만 같고 무관함

#### 커스텀 객체는 `equals` + `hashCode` 필수

```java
class Point { int x, y; }
Set<Point> s = new HashSet<>();
s.add(new Point(1, 2));
s.contains(new Point(1, 2));  // false — Object의 기본 equals는 주소 비교
```

→ 직접 만든 클래스를 컬렉션에 넣으려면 `equals`와 `hashCode` 둘 다 오버라이드.

## 4. HashSet 메서드

### 핵심 6개 (이것만 외우면 됨)

| 메서드 | 동작 | 반환값 | 시간복잡도 |
|---|---|---|---|
| `add(e)` | 원소 추가 | 추가됐으면 `true`, 이미 있으면 `false` | O(1) |
| `remove(o)` | 원소 제거 | 제거됐으면 `true`, 없었으면 `false` | O(1) |
| `contains(o)` | 있는지 체크 | `boolean` | O(1) |
| `size()` | 원소 개수 | `int` | O(1) |
| `isEmpty()` | 비었는지 | `boolean` | O(1) |
| `clear()` | 전부 비우기 | `void` | O(n) |

> 💡 `add`의 `false` 반환을 활용한 **첫 중복 감지** 패턴이 코테 단골.

### 집합 연산

```java
Set<Integer> a = new HashSet<>(Arrays.asList(1, 2, 3));
Set<Integer> b = new HashSet<>(Arrays.asList(2, 3, 4));

a.addAll(b);      // 합집합  → a = {1,2,3,4}
a.retainAll(b);   // 교집합  → a = {2,3}
a.removeAll(b);   // 차집합  → a = {1}
```

> ⚠️ **원본 a가 변경됨**. 보존하려면 `new HashSet<>(a)` 먼저 복사.

### 순회

```java
// for-each
for (int x : set) { ... }

// Iterator (순회 중 삭제 시 필수)
Iterator<Integer> it = set.iterator();
while (it.hasNext()) {
    if (조건) it.remove();
}
```

> ⚠️ HashSet은 **순서 보장 없음**. 순서 필요하면 `LinkedHashSet`(삽입 순) 또는 `TreeSet`(오름차순).

### 생성 패턴

```java
// 1. 빈 Set
Set<Integer> s = new HashSet<>();

// 2. int[] 배열로부터 (한 줄로는 불가, for 루프 필요)
int[] arr = {1, 2, 3};
Set<Integer> s = new HashSet<>();
for (int x : arr) s.add(x);

// 3. List로부터
Set<Integer> s = new HashSet<>(List.of(1, 2, 3));

// 4. Stream으로 박싱하면서
Set<Integer> s = Arrays.stream(arr).boxed().collect(Collectors.toSet());
```

> ⚠️ `new HashSet<>(arr)` ❌ — int[]는 Collection이 아님.
> `new HashSet<>(Arrays.asList(arr))` ❌ — `Set<int[]>`가 만들어짐 (배열 자체를 원소로 인식).

## 5. 체육복 디버깅 — 학습 포인트

### Bug 1 · 교집합 처리 시 `good++` 누락

```java
// ❌ 잘못된 코드
for (int i = 0; i < lost.length; i++) {
    if (res.contains(lost[i])) {
        res.remove(lost[i]);
        lost[i] = -1;       // 처리됨 표시는 하지만…
    }
}
```

**원인**: `good = n - lost.length`로 초기화했으므로 lost+reserve 둘 다 있는 학생은 "체육복 없음"으로 카운트된 상태. **자기 여벌을 입어서 체육복이 생겼는데** 그걸 반영 안 함.

```java
// ✅ 수정
if (res.contains(lost[i])) {
    res.remove(lost[i]);
    good += 1;              // 자기 여벌 입었으니 +1
    lost[i] = -1;
}
```

### Bug 2 · `lost` 정렬 안 함

"앞 번호(l-1) 먼저" 그리디는 lost가 **정렬된 상태**여야 정당화됨.

**반례**: `lost=[4,2], reserve=[3,5]`
- 정렬 X → 4가 먼저 3을 가져감 → 2 못 받음 → good = n-1
- 정렬 O → 2가 3을, 4가 5를 가져감 → good = n

```java
Arrays.sort(lost);   // ✅ 빌려주기 전에 정렬
```

### 왜 "앞 번호 먼저"가 최적인가?

각 reserve는 ±1만 빌려줌. **앞 번호부터 처리하면 뒤쪽 reserve가 더 유연하게 쓰일 가능성이 높아짐**.

`lost=[2,4], reserve=[3]`처럼 reserve가 양쪽 모두에게 줄 수 있을 때:
- 2에게 주면: 4는 5 시도 → 5가 있으면 살림
- 4에게 주면: 2는 1, 3 둘 다 없음 → 못 살림

→ 앞 번호 먼저가 항상 같거나 더 유리. (그리디 정당성)

### Bonus · 더 깔끔한 정석 풀이

체육복은 사실 **int[] 카운트 배열**이 표준.

```java
int[] clothes = new int[n + 2];   // padding으로 경계 처리
for (int i = 1; i <= n; i++) clothes[i] = 1;
for (int r : reserve) clothes[r]++;
for (int l : lost) clothes[l]--;
// 교집합은 +1, -1로 자동 처리 → 결과 1벌

for (int i = 1; i <= n; i++) {
    if (clothes[i] == 0) {
        if (clothes[i - 1] >= 2)      { clothes[i - 1]--; clothes[i]++; }
        else if (clothes[i + 1] >= 2) { clothes[i + 1]--; clothes[i]++; }
    }
}
```

**얻을 패턴 2가지:**

1. **카운트 배열** — 번호/인덱스 기반 수량 관리
2. **Padding (`n + 2`)** — 양 끝 경계 처리를 자동화

## 6. 코테에서 바로 쓰는 패턴

### ① 중복 제거

```java
Set<Integer> set = new HashSet<>();
for (int x : arr) set.add(x);
```

→ O(n). 정렬 후 인접 비교(O(n log n))보다 빠름.

### ② 첫 중복 찾기 (`add` 반환값 활용)

```java
Set<Integer> seen = new HashSet<>();
for (int x : arr) {
    if (!seen.add(x)) return x;   // add가 false면 이미 있던 것
}
```

### ③ 두 배열의 공통 원소

```java
Set<Integer> setA = new HashSet<>();
for (int x : a) setA.add(x);

for (int x : b) {
    if (setA.contains(x)) { ... }
}
```

→ O(|a| + |b|). 이중 for문 O(|a|·|b|) 대신 항상 이렇게.

### ④ Lookup용 캐시 (체육복 패턴)

```java
Set<Integer> reserveSet = new HashSet<>();
for (int r : reserve) reserveSet.add(r);

for (int l : lost) {
    if (reserveSet.contains(l)) { ... }   // O(1)
}
```

→ `ArrayList.contains`를 루프 안에서 쓰면 O(n·m), Set으로 바꾸면 O(n+m).

## ❌ 하지 말 것

```java
// 1) binarySearch 결과를 > 0으로 비교
if (Arrays.binarySearch(arr, p) > 0)        // 0 인덱스 누락!
if (Arrays.binarySearch(arr, p) != -1)      // 없을 때 -1만 나오는 게 아님

// 2) 정렬 안 하고 binarySearch
int[] arr = {3, 1, 5};
Arrays.binarySearch(arr, 5);                // 결과 undefined

// 3) int[]를 HashSet 생성자에 직접 전달
new HashSet<>(arr);                          // 컴파일 에러
new HashSet<>(Arrays.asList(arr));           // Set<int[]> 됨!

// 4) ArrayList.contains를 루프 안에서 반복 호출
for (int x : a) {
    if (list.contains(x)) { ... }            // O(n) × m번 = O(n·m)
}

// 5) Map에 contains 호출
map.contains("key");                         // 컴파일 에러 (containsKey/Value)

// 6) 커스텀 객체를 Set에 넣고 equals/hashCode 안 만듦
Set<Point> s = new HashSet<>();
s.add(new Point(1, 2));
s.contains(new Point(1, 2));                 // false (주소 비교)
```
