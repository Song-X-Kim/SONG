## 한눈에 보기

| 메서드 | 소속 | 시간복잡도 | 핵심 포인트 |
|---|---|---|---|
| `Math.log(x)` | `java.lang.Math` | O(1) | 자연로그(밑 e). 밑 변환 시 부동소수점 오차로 자릿수 1 어긋남 |
| `Math.pow(a,b)` | `java.lang.Math` | O(1) | 항상 `double` 반환. 27이 26.999...로 나올 수 있음 |
| `Arrays.fill(arr,v)` | `java.util.Arrays` | O(n) | 1차원 배열 전체를 v로 채움. 2D는 행마다 반복 |
| `String.join(d,...)` | `java.lang.String` | O(n) | `CharSequence`만 받음. `int[]`/`Integer[]` 불가 |
| `StringBuilder` | `java.lang` | append O(1) | 정수→문자열 누적은 이게 정석 |

> **한 줄 요약**: "0 없는 진법" 문제는 자릿수를 먼저 구하려 하지 말고, **나머지가 0일 때 윗자리에서 1을 빌려오는** 방식이 정석이다. `Math.log`/`Math.pow`로 자릿수를 구하면 부동소수점·경계·캐스팅 함정이 한꺼번에 터진다.

## 1. Math.log / Math.pow

### Math.log — 밑 3인 로그는 없다
`Math`에는 밑 3 로그 메서드가 없어서 밑 변환 공식을 써야 한다.

```java
double v = Math.log(9) / Math.log(3);   // log₃9 = 2.0 (이론상)
```

**규칙**
- `Math.log(x)` = 자연로그 ln (밑 e)
- `Math.log10(x)` = 상용로그 (밑 10)
- 밑 3 로그 = `Math.log(x) / Math.log(3)` (밑 변환)

**함정 — 자릿수 구하기에 쓰면 안 됨**
```java
// n=9: log₃9 = 2.0 이어야 하지만 1.9999... 또는 2.0000...1 가능
int len = (int)(Math.log(9) / Math.log(3)) + 1;   // 경계값에서 1 어긋남
```

### Math.pow — 항상 double, 정수 기대 금지
```java
Math.pow(3, 3);   // → 27.0 (double). 구현에 따라 26.999... 가능
```

**규칙**
- 반환 타입은 무조건 `double`
- 정수 거듭제곱이 필요하면 곱셈 루프나 누적 변수를 쓴다
- `(int)`/`(long)` 캐스팅해도 `double` 정밀도(2^53 초과 시 정수 부정확)는 못 피함

```java
// 정수 거듭제곱이 필요하면
long pow = 1;
for (int i = 0; i < k; i++) pow *= 3;   // 오차 0
```

## 2. (int) 캐스팅 위치

캐스팅을 **어디까지 씌우느냐**로 결과가 달라진다. 연산자 우선순위 문제다.

```java
// 나쁜 예: Math.pow에만 캐스팅 → 26.999...가 26으로 깎인 뒤 계산
n - ((int) Math.pow(3, len) - 1) / 2

// 좋은 예: 나눗셈까지 double로 한 뒤 마지막에 캐스팅 → 27.0 거쳐 정확
n - (int) ((Math.pow(3, len) - 1) / 2)
```

**규칙**
- `(int) expr` 의 `(int)`는 **바로 뒤 하나**에만 붙는다 (`(int) a * b` = `((int)a) * b`)
- `double` 연산은 마지막에 한꺼번에 캐스팅해야 중간 오차가 안 끼어든다

**왜 터졌나**: `(int)Math.pow(3,3)`가 26이 되면 `(26-1)/2 = 12`(정수나눗셈). 정답 13보다 1 작아 `target`이 1 커지고, 그 1이 최상위 자리로 흘러 자릿값이 4가 됨 → `rule[4-1]=rule[3]` → `ArrayIndexOutOfBoundsException`.

## 3. += 의 숨은 캐스팅

```java
int sum = 0;
sum = sum + Math.pow(3, i) * x;   // 컴파일 에러: double → int
sum += Math.pow(3, i) * x;        // 컴파일 통과! 몰래 (int) 캐스팅
```

**규칙 (JLS §15.26.2)**
- `a += b` 는 내부적으로 `a = (T)(a + b)` (T는 a의 타입)
- `=` 는 좁히는 캐스팅을 자동으로 안 해줘서 에러
- `+=` 는 캐스팅이 명세에 포함돼 **에러 없이 통과** → 소수점 버림 + 오버플로 위험

**교훈**: `+=`가 에러 안 난다고 안전한 게 아니다. 오히려 조용히 틀려서 더 위험.

## 4. String.join

```java
int[] arr = {1, 2, 3};
String.join("", arr);   // 컴파일 에러
```

**규칙**
- `String.join`은 `CharSequence...` 또는 `Iterable<? extends CharSequence>`만 받음
- `int[]`, `Integer[]`, `List<Integer>` 전부 불가 — **문자열류만**

```java
String[] s = {"1", "2", "3"};
String.join("", s);   // "123"
```

**int[] → String 정석**
```java
StringBuilder sb = new StringBuilder();
for (int x : arr) sb.append(x);
String result = sb.toString();   // "123"
```

## 5. Arrays.fill

```java
int[] arr = new int[5];
Arrays.fill(arr, 1);          // [1,1,1,1,1]
Arrays.fill(arr, 1, 4, 9);    // 범위 [from,to) → 인덱스 1,2,3만 9
```

**규칙**
- 1차원 배열만 채움
- 범위 지정 시 `to`는 미포함 `[from, to)`
- 2D는 `for (int[] row : board) Arrays.fill(row, v);`

**이번 문제에서의 쓰임**: "0이 안 나오게 모든 자리를 1로 깔고 출발"하는 초기화로 사용. 발상 자체는 맞았다.

## 디버깅 학습 포인트

### 잘못된 풀이 (자릿수를 먼저 구하는 접근)

```java
int[] rawA = new int[(int)(Math.log(n) / Math.log(3)) + 1];   // 자릿수
Arrays.fill(rawA, 1);
int target = n - ((int) Math.pow(3, rawA.length) - 1) / 2;
if (n < 0) n += Math.pow(3, rawA[rawA.length - 1]);            // 죽은 코드
for (int i = rawA.length - 1; i >= 0; i--) { ... }
for (int i : rawA) { if (i <= 0) continue; sb.append(rule[i-1]); }  // 정방향 + continue
```

### 왜 실패했나 — 증상은 여럿, 원인은 하나

겪은 증상: **음수 인덱스 / 인덱스 4 에러 / 자릿값 0 나옴**.
→ 전부 **`len`(자릿수)이 틀렸다**는 단일 원인에서 파생.

| 증상 | 직접 원인 | 뿌리 |
|---|---|---|
| n=9가 "1" 나옴 | target 음수 | log₃9=2 → len 1 더 잡힘 |
| 인덱스 3 에러 | 자릿값 4 발생 | len 1 모자람 (경계 공식 틀림) |
| 출력 뒤집힘 | 정방향 출력 | 최상위가 `rawA[len-1]`인데 0부터 붙임 |

**왜 log로 자릿수를 못 잡나**
- `log₃`는 "3의 몇 제곱"을 잼 → 경계가 `3, 9, 27`(3의 거듭제곱)
- 124나라 자릿수 경계는 `3, 12, 39` (등비수열 합)
- 두 자가 어긋나서 거듭제곱 지점(9, 27)마다 1씩 틀림

```
log₃ 경계:        1 ... 3 ... 9 ... 27
124나라 경계:    1~3 | 4~12 | 13~39    ← 9는 2자리 한가운데
```

### 정답 (자릿수 직접 유도 버전)

```java
int len = 1;
while ((Math.pow(3, len + 1) - 3) / 2 < n) len++;   // len자리 최댓값 < n 이면 늘림
```

**`-3`의 정체**: len자리까지 누적 개수 = 등비수열 합
`3 + 3² + ... + 3^len = 3(3^len - 1)/2 = (3^(len+1) - 3)/2`.
첫항이 3이라 분자에 `-3`이 남는다. (1차 시도 때 `-1`로 잘못 써서 13에서 터짐 — 보통 진법이면 `-1`이 맞지만 124나라는 1부터 세서 `-3`)

## 코테에서 바로 쓰는 패턴

### "0 없는 진법(bijective base-k)" — 정석 풀이

자릿수를 미리 구하지 않는다. **나머지가 0이면 그 자리를 최댓값으로 쓰고 몫에서 1을 뺀다.**

```java
class Solution {
    public String solution(int n) {
        String[] rule = {"4", "1", "2"};   // 나머지 0→"4", 1→"1", 2→"2"
        StringBuilder sb = new StringBuilder();
        while (n > 0) {
            int r = n % 3;
            sb.append(rule[r]);
            n = (r == 0) ? n / 3 - 1 : n / 3;   // 0이면 윗자리에서 1 빌림
        }
        return sb.reverse().toString();
    }
}
```

| n | n%3 | append | 다음 n |
|---|---|---|---|
| 3 | 0 | "4" | 3/3-1 = 0 → "4" |
| 4 | 1 | "1" | 1 → 다시 1%3=1 "1" → "11" |
| 10 | 1 | "1" | 3 → 0 "4" → reverse "14" |

**복잡도**: 시간 O(log₃n), 공간 O(log₃n).

**같은 패턴이 나오는 문제**
- 엑셀 열 이름 (1=A, 26=Z, 27=AA) → bijective base-26
- 0을 안 쓰는 모든 진법 변환

핵심 통찰: **0이 없는 진법 = 나머지 0일 때 몫에서 1 빌려오기**. 이 한 줄(`n/3 - 1`)이 자릿수 계산·경계·캐스팅 함정을 전부 우회한다.

## 하지 말 것

- `Math.log`로 진법 자릿수 구하기 → 거듭제곱 경계에서 1 어긋남
- `Math.pow` 결과를 정수로 신뢰 → `double`이라 27이 26.999... 가능
- `((int) Math.pow(...) - 1) / 2` → 캐스팅을 먼저 하지 말 것, 식 전체를 감싸라
- `int sum += Math.pow(...)` → 에러 안 나도 몰래 캐스팅+오버플로
- `String.join("", intArray)` → 문자열류만 받음
- 등비수열 합 분자에 `-1` (보통 진법 습관) → 1부터 세는 진법은 `-3`
- `for (int i : rawA)` 정방향 출력 → 최상위 자리가 끝 인덱스라 뒤집힘
- 자릿수 먼저 구하는 접근에 집착 → "0 없는 진법"은 나머지 연산이 훨씬 짧음
