## 1️⃣ Math.max()

### 기본
- `java.lang.Math`의 **정적 메서드** (import 불필요)
- **인자 2개 전용** (JS처럼 가변 인자 ❌)
- 오버로드 4가지: `int`, `long`, `float`, `double`

```java
Math.max(3, 7);        // 7
Math.max(3.0, 7.0);    // 7.0
```

### 배열/리스트 최댓값

```java
// for문 (코테 추천)
int max = Integer.MIN_VALUE;
for (int n : arr) max = Math.max(max, n);

// 스트림
int max = Arrays.stream(arr).max().getAsInt();
int max = Collections.max(list);
```

| 방법 | 추천 상황 |
|---|---|
| `for문` | **코테 (가장 빠름)** |
| `Arrays.stream` | 짧게 쓰고 싶을 때 |
| `Collections.max` | List/Set |

## 2️⃣ String은 immutable (불변)

### 핵심 함정

```java
s.replaceAll(" ", "");      // ❌ 반환값 버림 → s 안 바뀜
s = s.replaceAll(" ", "");  // ✅ 재할당 필수
```

> `String`의 모든 변형 메서드는 **새 String을 반환**한다. 원본은 절대 안 바뀜.

### replace vs replaceAll
- `replace(CharSequence, CharSequence)`: 단순 문자열 치환, **빠름**
- `replaceAll(String, String)`: **정규식** 기반, 오버헤드 있음
- 단순 치환이면 `replace` 우선

## 5️⃣ 프로그래머스 "최댓값과 최솟값"

### ❌ 잘못된 접근: char 단위 비교

입력 `"1 2 3 4"`는 **숫자 4개를 공백 구분**한 것이지 문자 7개가 아님.

| 문자 | `'1'` | `' '` | `'2'` | ... | `'4'` |
|---|---|---|---|---|---|
| 아스키 | 49 | **32** | 50 | ... | 52 |

- 공백(32)이 숫자 문자(48~57)보다 작아서 **최솟값=공백**으로 잡힘
- 음수(`"-4"`)는 **두 글자** → char 하나로 비교 불가
- 공백을 제거해도 본질 한계는 그대로

### ✅ 정답: split + parseInt

```java
class Solution {
    public String solution(String s) {
        int min = Integer.MAX_VALUE;
        int max = Integer.MIN_VALUE;
        
        for (String token : s.split(" ")) {
            int n = Integer.parseInt(token);
            min = Math.min(min, n);
            max = Math.max(max, n);
        }
        
        return min + " " + max;
    }
}
```

**복잡도:** 시간 O(n), 공간 O(n)

## 6️⃣ toCharArray() 동작

### 핵심
- String 내부 문자들을 **복사**해 새 `char[]` 반환
- String이 immutable이라 원본 노출 안 함
- 반환된 배열 수정해도 원본 String 영향 X

```java
String s = "abc";
char[] arr = s.toCharArray();  // 새 배열 생성
arr[0] = 'X';
System.out.println(s);  // "abc" ← 영향 없음
```

### JDK 9+ Compact Strings
- 내부적으로 `char[]`가 아닌 `byte[]` + coder 플래그
- LATIN1이면 1바이트, UTF-16이면 2바이트
- `toCharArray()` 호출 시 char로 **변환** + 새 배열 생성

### toCharArray() vs charAt()

| 항목 | `toCharArray()` | `charAt(i)` |
|---|:---:|:---:|
| 추가 배열 | O(n) | 없음 |
| 단일 호출 | O(n) | O(1) |
| 전체 순회 | O(n) | O(n) |
| 인덱스 사용 | ❌ | ✅ |
| 추천 상황 | 인덱스 불필요 | **일반적으로 무난** |

## 7️⃣ ⚠️ 핵심 원칙: for문 안 O(n) 호출 금지

### O(n) → O(n²) 함정

```java
// ❌ 매 반복마다 새 배열 생성
for (int i = 0; i < n; i++) {
    char c = s.toCharArray()[i];
}

// ✅ 한 번만 만들고 재사용
char[] arr = s.toCharArray();
for (int i = 0; i < arr.length; i++) { ... }
```

### O(n) 메서드 함정 모음

| 메서드 | 복잡도 | 대안 |
|---|---|---|
| `s.toCharArray()` | O(n) | `charAt(i)` |
| `s.split(regex)` | O(n) | 루프 밖에서 1회 |
| `s.substring(i, j)` | O(j-i) | 인덱스로 직접 비교 |
| `s.contains(x)` | O(n·m) | 필요시 1회만 |
| `list.contains(x)` (ArrayList) | O(n) | **`HashSet` → O(1)** |
| `String + String` 누적 | O(n²) 누적 | **`StringBuilder`** |

### 원칙
> **"변하지 않는 값을 가공한 결과"는 루프 밖에서 한 번만 계산**

## 8️⃣ split의 O(n) 처리

```java
String[] tokens = s.split(" ");  // 루프 "밖"에서 O(n) 한 번
for (String token : tokens) {     // 이후 O(n)
    ...
}
// 합계 O(n) ✅
```

### split vs StringTokenizer

| 방법 | 정규식 | 속도 | 가독성 |
|---|:---:|:---:|:---:|
| `split` | ✅ | 보통 | 👍 |
| `StringTokenizer` | ❌ | **빠름** | 보통 |

```java
StringTokenizer st = new StringTokenizer(s, " ");
while (st.hasMoreTokens()) {
    int n = Integer.parseInt(st.nextToken());
}
```

- 일반 코테: `split` (가독성)
- 입력 큰 백준식: `BufferedReader` + `StringTokenizer` 정석

## 📌 한 줄 요약

1. **String immutable** → 변형 메서드는 항상 재할당
2. **char + char ≠ 문자열 연결** → StringBuilder는 `.append()` 체이닝
3. **숫자 비교는 숫자로** → `parseInt` 거쳐서
4. **for문 안 O(n) 호출 금지** → 루프 밖에서 한 번만
5. **toCharArray vs charAt** → 인덱스 없으면 둘 다 OK, 메모리는 charAt 유리
